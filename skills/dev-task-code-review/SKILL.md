# Внешнее code review

Прими итоговый diff всех затронутых репозиториев, `proposal.md`, `spec.md`, результаты тестов и ручных проверок, а также известные ограничения.

Пропусти внешний review только если одновременно нет новой логики и итоговый diff меньше 10 строк. В этом случае верни явную причину пропуска для PR.

Для остальных изменений передай независимому reviewer или субагенту весь входной контекст и попроси проверить:

* соответствие требованиям и Acceptance Criteria;
* корректность решения и обратную совместимость;
* баги, пропущенные edge cases и обработку ошибок;
* читаемость, нейминг, дублирование, сложность, coupling и cohesion;
* достаточность тестов;
* применимые security и performance-риски.

После review классифицируй каждое замечание как обязательное, рекомендательное или нерелевантное. Исправь обязательные замечания. Для отклонённых замечаний укажи краткое обоснование. Повторно запусти проверки, затронутые исправлениями, и обнови `spec.md`, если фактическое решение существенно изменилось.

Не создавай отдельный этап повторной self-reflection: достаточно проверить исправленный diff и связанные сценарии. В конце верни список замечаний, принятые решения, повторные проверки и остаточные риски. Не выполняй commit, push или создание PR.
