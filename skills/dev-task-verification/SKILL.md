# Проверка готовности

Прими `TASK-ID`, `artifact_dir`, `proposal.md`, `spec.md`, итоговый diff, результаты автоматических проверок и известные ограничения. Веди отчёт и сообщения на русском языке, если правила проекта или репозитория явно не требуют другого языка. Если одного из ключевых входов нет, запроси его или явно зафиксируй ограничение.

Сопоставь фактическую реализацию со всеми Acceptance Criteria из `proposal.md`. Проверь применимые сценарии:

* корректные и невалидные входные данные;
* пустые значения, `null`, границы и лимиты;
* обработку ошибок;
* обратную совместимость;
* поведение, которое не должно было измениться.

По возможности подними проект и вручную проверь изменённую функциональность через UI, API или иной подходящий интерфейс. Пропусти ручную проверку только если изменение тривиально, не содержит новой логики, надёжно покрыто автоматическим тестом и локальный запуск непропорционально сложен. Зафиксируй причину для будущего PR.

Если проверку невозможно выполнить из-за окружения, явно сообщи:

> ⚠️ Не удалось проверить `{что}`. Для проверки требуется `{что необходимо}`.

Выполни self-review итогового diff:

* проверь соответствие `proposal.md` и `spec.md`;
* найди лишние изменения, очевидные баги и пропущенные edge cases;
* упрости решение, если это не меняет согласованный scope;
* оцени достаточность тестов и применимые security, performance, observability-риски.

Исправь найденные проблемы и повторно запусти затронутые проверки.

В конце запиши результат этапа в `{artifact_dir}/{TASK-ID}/stage-results/verification.json` по схеме `$dev-task-workflow/references/stage-result-schema.md`: `stage: "verification"`, `status`, `summary`, `artifacts` (изменённые файлы), `warnings`, при ошибке — `error` (код `test_failed`), `suggested_next` — `"code-review"` при успехе, `"back_to_implementation"` при `test_failed`. Затем верни DoD-отчёт: выполненные Acceptance Criteria, тесты, ручные проверки или причину пропуска, непроверенные сценарии, известные ограничения и готовность к внешнему review. Не выполняй внешний review, commit, push или создание PR.
