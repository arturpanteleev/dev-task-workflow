# Реализация задачи

Прими утверждённые `proposal.md` и `spec.md`, список затронутых репозиториев, base-ветку и имя целевой ветки. Веди сообщения и итоговый отчёт на русском языке, если правила проекта или репозитория явно не требуют другого языка. Не начинай работу, если план не утверждён или входы неполны.

Перед любыми git write-операциями выполни для каждого репозитория:

```bash
bash scripts/task-preflight.sh \
  --repo /absolute/path/to/repository \
  --base {base-branch} \
  --branch feature/{task-slug}/{TASK-ID}
```

Если preflight нашёл блокер, остановись и сообщи его. Только после успешного preflight переключись на base-ветку, выполни `pull origin <base>` и создай целевую ветку.

Реализуй только изменения из утверждённого плана. Не исправляй соседние проблемы, не обновляй зависимости и не меняй архитектуру без отдельного согласования. Зафиксируй найденные несвязанные проблемы отдельно.

Добавь или обнови необходимые тесты. Для новой содержательной логики по возможности покрой happy path, значимый edge case и негативный сценарий. Применяй цель 90% coverage к новой логике только если coverage можно корректно измерить; не добавляй малоценные тесты ради процента.

Не добавляй unit-тест, только если нет новой логики и поведение надёжно покрывает существующий или обновлённый тест более высокого уровня. Объясни причину для будущего PR. Добавь или обнови integration-тесты при изменении взаимодействия компонентов, API, хранилища или значимого пользовательского сценария.

Запусти применимые линтеры, статические проверки и автоматические тесты. В конце сообщи изменённые репозитории, выполненные проверки, результаты и известные ограничения. Не выполняй commit, push или создание PR.
