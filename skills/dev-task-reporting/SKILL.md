# Итоговый отчёт задачи

Прими `TASK-ID`, `artifact_dir`, `workflow_context`, proposal, spec, проверенную сводку diff, результаты verification и review, ограничения, delivery metadata и **уже заполненный оркестратором** `{artifact_dir}/{TASK-ID}/report-data.json`. Файл содержит инкрементально собранные данные всех предыдущих этапов.

Запускай финальный reporting только после успешного создания хотя бы одного PR для каждого затронутого репозитория. Если PR отсутствует, верни блокер и не создавай финальный отчёт. Не жди merge и не утверждай, что изменение уже работает в production.

## Подготовка данных

Перед началом прочитай `references/report-data-schema.md`.

Прочитай существующий `{artifact_dir}/{TASK-ID}/report-data.json`. Заполни оставшиеся незаполненные поля (`oversight.approval_gates`, `oversight.autonomous_decisions`, `oversight.plan_deviations`, `attention`, `next_steps`, `links`), используя только сведения, полученные в ходе задачи. Не проводи дополнительное продуктовое исследование.

Разделяй подтверждённые факты, решения, допущения, ожидаемый и измеренный эффект. Для отсутствующей информации используй `Не зафиксировано`, а для ещё не измеренного результата — `Не измерялось`. Не включай полный diff, сырые логи, секреты, токены, персональные или иные чувствительные данные.

Сделай верхний уровень отчёта пригодным для быстрой проверки владельцем автономного workflow. Явно выдели:

* бизнес-проблему и выбранное решение;
* точки, требующие внимания;
* самостоятельные решения агента;
* отклонения от proposal и spec;
* непроверенные сценарии и ограничения;
* статусы Acceptance Criteria, проверок, review и PR.

Поддерживай несколько репозиториев, commits и PR в одном отчёте.

## Генерация и проверка

Работай из каталога skill или используй абсолютные пути к его ресурсам:

```bash
python3 scripts/validate_report.py \
  --data {artifact_dir}/{TASK-ID}/report-data.json

python3 scripts/render_report.py \
  --input {artifact_dir}/{TASK-ID}/report-data.json \
  --output {artifact_dir}/{TASK-ID}/report.html

python3 scripts/validate_report.py \
  --data {artifact_dir}/{TASK-ID}/report-data.json \
  --html {artifact_dir}/{TASK-ID}/report.html
```

Исправь ошибки данных или генерации и повтори проверки. Повторный запуск должен безопасно обновлять оба файла без создания дубликатов.

Не публикуй отчёт, не добавляй GitHub Pages или CI artifacts. Не создавай отдельную печатную версию и print-стили. Итоговый HTML должен быть автономным, адаптивным, семантическим, доступным и не загружать внешние CSS, JavaScript, шрифты или изображения.

В конце покажи путь к `report.html`, перечисли PR, основные точки внимания и результат валидации. Если генерация не удалась после уже выполненного delivery, не изменяй Git-состояние и сообщи, что workflow остаётся незавершённым до повторной генерации отчёта.
